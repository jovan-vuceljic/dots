# Test the new `.dots` wm config (branch `migrate-new-dots`)

This branch makes `dots-wm` byte-identical to what the new `~/.dots` (stow
monorepo) deploys for host **wm** = `common + gui + wm` layered, host wins.
Deploy it with your existing dots-wm mechanism, confirm nothing breaks, then
migrate wm to the real `~/.dots`.

Delta vs `main`: **43 added, ~54 modified, ~12 removed** (all removals are junk
or intentional restructures — see the checklist below).

---

## 0. Prerequisite — confirm you are on the wm machine

Do NOT run this on the lw box: lw already runs the new `~/.dots` and every file
would conflict. Sanity check — this must resolve into `dots-wm`, not `.dots`:

```fish
readlink -f ~/.config/hypr/hyprland.conf
```

If it points into `~/.dots/...`, stop — this machine is already migrated.

Also confirm HyDE is present (wm already runs it — see `HYDE-UPDATE.md`):

```fish
test -f ~/.local/share/hyde/hyprland.conf && echo present
```

---

## 1. Deploy the branch

```fish
cd ~/projects/dots/dots-wm
git stash            # only if you have uncommitted changes on main
git checkout migrate-new-dots
stow --no-folding -R -t ~ -d ~/projects/dots dots-wm
```

- `-R` = **restow**: reconciles the 43 new links and drops the 12 stale ones.
  Just switching branch is not enough — it only updates already-linked files.
- The repo ships a `.stow-local-ignore` so `.git`, `LICENSE`, `README.md`,
  `.gitignore`, and this file aren't linked into `~`.
- If you deploy dots-wm some other way, use that command but make sure it
  **re-links** (adds new, removes deleted), not just refreshes existing files.

### If stow reports a conflict
Means a new file's target already exists as a **real file** (not a stow link).
Likely paths: `~/.config/tmux/`, `~/.librewolf/`, `~/.config/presenterm/`,
`~/.config/tuios/`, `~/.config/waybar/{includes,layouts}/`,
`~/.config/zellij/themes/`.

Either move the real file aside:
```fish
mv ~/.config/tmux/tmux.conf ~/.config/tmux/tmux.conf.pre-migrate
```
or adopt it into the repo working tree to diff first, then re-stow:
```fish
stow --no-folding -R --adopt -t ~ -d ~/projects/dots dots-wm
git -C ~/projects/dots/dots-wm diff   # inspect what got pulled in
```

## 2. Verify (the intentional restructures — check each still works)

| Area | What changed | Check |
|------|--------------|-------|
| **hypr** | theme now sourced from `~/.local/share/hyde/hyprland.conf`; repo `themes/*` and `workspaces.conf` dropped | `hyprctl reload` — no errors; workspaces + theme intact |
| **waybar** | `layouts/custom.*` replaces `config.ctl` / `config.jsonc` / `style.css` | restart waybar — bar renders, styling correct |
| **tmux** | `~/.tmux.conf` -> `~/.config/tmux/tmux.conf` (+ scripts) | new tmux session picks up config |
| **opencode** | `opencode.jsonc` -> `opencode.json` (+ `openai-gpt.jsonc`) | opencode starts with your settings |
| **nvim** | `codecompanion.lua` removed (plugin gone) | `nvim` opens with no missing-config errors |
| **fish** | adds ssh-agent + extra functions | new shell loads clean |

Two **runtime deps** that must already exist on wm (generated by HyDE, not in
the repo): `~/.local/share/hyde/hyprland.conf` and a wallbash-generated
`~/.config/waybar/theme.css`. If HyDE has ever applied a theme on wm, they exist.

---

## 3. Revert (fully reversible — nothing is committed, `main` untouched)

```fish
cd ~/projects/dots/dots-wm
git checkout main
stow --no-folding -R -t ~ -d ~/projects/dots dots-wm   # restore the old link set
git stash pop        # if you stashed in step 1
```

---

## 4. If it's good — migrate wm to the real `~/.dots`

Once satisfied, drop dots-wm and switch wm to the unified repo:

```fish
cd ~/.dots
git pull
./install.sh -n wm   # dry-run preview
./install.sh wm      # deploy (layers common -> gui -> wm)
```

`install.sh -a wm` on first run if wm still has real (non-symlink) config files
to adopt. After that, delete the old dots-wm deployment.

## HyDE on wm (summary — full detail in `HYDE-UPDATE.md`)

- **wm already runs HyDE** (the old config on `main` sources `~/.local/share/hyde/hyprland.conf`), just an older version than lw. So a HyDE update is **not required** to test this branch — test the dots on wm's current HyDE first.
- Updating HyDE later (to align wm with lw) is **only partially reversible**: config is recoverable via git + `~/.dots/bin/reconcile-hyde.sh`, but packages and `~/.local/share/hyde/*` are not, and there are no system snapshots. Back up first.
- **See `HYDE-UPDATE.md`** for the full explanation and the optional update/revert steps.
